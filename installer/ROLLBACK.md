# Ручной откат 0.3.0 → 0.2.3

Автоматического rollback нет. Сессия находится в RAM и не переносится между
версиями: сначала вставьте нужные снимки, затем выйдите через tray → Exit.
Не завершайте процесс принудительно.

## Сохранённый baseline

- Исходники: неизменяемый тег [v0.2.3](https://github.com/nickkho0201/ScreenIt/tree/v0.2.3).
- Официальные файлы: [release 0.2.3](https://github.com/nickkho0201/ScreenIt/releases/tag/v0.2.3).
- SHA-256 установщика `ScreenIt-Setup-0.2.3.exe`:
  `6e9a4129a07453b885f6f7d538472398616e26434fad4fd08a1a115af15ac73f`.
- SHA-256 portable `ScreenIt-0.2.3-win-x64-portable.zip`:
  `e943b8d9596463fb65810ab5d94c03d1516d9002b14338d8b97f54524fcb1824`.

Проверьте скачанные файлы через `Get-FileHash -Algorithm SHA256` и сравните
с этими значениями и `SHA256SUMS.txt` предыдущего выпуска. Старые assets не
пересобираются и не заменяются новым релизом.

## Настройки и переносная копия

1. После выхода сохраните копию `%LOCALAPPDATA%\ScreenIt\settings.json`, если
   файл существует, в отдельное безопасное место. Это настройки, не снимки.
2. Распакуйте официальный portable 0.2.3 в **новую пустую папку**, не поверх 0.3.0.
3. Запустите из неё `ScreenIt.App.exe`. Обе версии используют один mutex и один
   файл настроек, одновременно работать не могут.
4. 0.2.3 не знает поле `design` и использует свой классический интерфейс.
   Schema остаётся 2; старый loader сохраняет неизвестные поля при Save.
   Тема, язык, shortcuts, modifier и Clear preference совместимы. Резервную
   копию всё равно сохраните; восстановление делайте только при закрытом app.
5. Не включайте автозапуск portable, если не хотите перенаправить существующую
   запись Windows на эту копию. Updater предлагает только более новые версии,
   а не откат; после возврата он может снова предложить 0.3.0.

## Установленная копия

Проверено при подготовке 0.3.0: официальный portable 0.2.3 проходит production
smoke после 0.3.0; настоящий loader 0.2.3 читает и сохраняет synthetic settings
0.3.0 без потери полей. Downgrade установщика на пользовательской установке не
исполнялся; это не заявление о проверенном setup UX.

После выхода и backup настроек можно вручную запустить официальный setup 0.2.3
с тем же каталогом установки. AppId, mutex, путь и settings location сохранены;
старый Inno `[Files]` использует `ignoreversion`. Не удаляйте настройки и не
пытайтесь устанавливать поверх работающей программы. Обычный downgrade setup
на пользовательской установке не является автоматическим rollback и требует
ручной проверки версии в About после запуска. Если setup не завершился,
используйте отдельно распакованную portable 0.2.3, не удаляя данные вслепую.

## Откат кода в main

Не перемещайте `v0.2.3`, не делайте force-push/reset опубликованной main.
Для возврата к исходникам используйте новую ветку от `v0.2.3`; для отмены
интеграции в main — отдельный reviewed revert-коммит. Весь release diff
интегрирован одним коммитом `8191fdd7185c021444f2097676d8ccabc51c36d8`:

```powershell
git switch -c codex/rollback-0.3.0 main
git revert 8191fdd7185c021444f2097676d8ccabc51c36d8
```

Это инструкция на случай необходимости, не выполненный откат. После неё нужны
review/build/tests; последующие изменения main могут потребовать разрешения
конфликтов. Revert возвращает код и metadata 0.2.3, но сам по себе не меняет
GitHub Latest и не понижает установленные приложения. Публикация исправленного
релиза и смена GitHub Latest — отдельное явное действие владельца.
